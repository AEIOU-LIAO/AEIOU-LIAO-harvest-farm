# 场景设计：方案 C（精细主场景 + 远景 + 传送到独立场景）

甲方 2026-10-26 确认。目标：**画面精美细腻，同时在手机浏览器上流畅**。

## 1. 原则

1. **一个场景一份预算。** 手机浏览器的显卡算力是固定的，同屏东西越多，每样东西分到的越少。所以不再把所有地方塞进一张大地图，而是每个地方做成独立场景（`content/zones.jsonc` 一条记录 = 一个场景），进入时加载、离开时释放，各自独享全部预算。
2. **家园只做精细的农场。** 可走范围 = 农场半径 + 14 米（离农场中心 122 米，到树林前为止）。外面的丘陵、森林、湖、远山只是远景：只能看、不能走，用来营造开阔感，做得很省。
3. **其他地方从传送阵进。** 家园东南边的传送阵（漫游时走上去按「传送阵 · 去别的地方」），或者左边的「地图」按钮，都打开世界地图选目的地；切换有淡入淡出。
4. **数量让位给质量。** 宁可少摆几样东西，每样都做精细；超预算时由美术和程序一起减，不靠运行时自动降画质兜底（自动降画质只是最后的保险）。

## 3. 每个场景的手机预算

以中端安卓手机、微信 / Chrome 浏览器为准，默认画质：

| 项目 | 预算 | 说明 |
|---|---|---|
| 同屏三角面 | ≤ 30 万 | 包括阴影那一遍 |
| 绘制次数 | ≤ 150（目标），≤ 250（上限） | 每个单独的模型 / 材质组合算一次；同类东西要实例化或合并 |
| 贴图显存 | ≤ 150 MB | 以后换手机压缩贴图格式（KTX2）后大约能省 3/4 |
| 阴影 | 1 张、只覆盖镜头附近约 50 米 | 小东西（半径 < 0.45 米）和扁平的东西（高 < 0.35 米）自动不投影 |
| 帧率 | 稳定 30 帧以上（不抖比高更重要） | — |

**怎么看：** 设置里打开「性能信息」，屏幕上会显示帧率、三角面、绘制次数（超预算标红）。

## 4. 家园现在的实测（v3.20.0，手机尺寸 390 × 780，本地软件渲染）

| 视角 | 三角面 | 绘制次数（最后一遍） | 结论 |
|---|---|---|---|
| 俯视 | 30.5 万 | 287 | 三角面达标；绘制次数超目标，主要是第一片菜地 20 块未开垦地块（每块 3 次） |
| 漫游 | 17~27 万 | 63~131 | 达标 |

这一版做了：可走范围收回到农场；远景世界 1.6 公里 → 0.84 公里，森林约少 3/4；远景森林每块树干树冠合成一次绘制；果园装饰、云合并；花草分块 72 → 150 米；小东西不投影（每帧阴影绘制少 200 多次）；农场大树、未开垦地块的草、远处地形减面。

**v3.20.1**：未开垦地块已合批（俯视最后一遍绘制 289 → 232）。下一步：已开垦地块的田垄合批。

## 5. 给美术的统一要求（每个场景都适用）

- 按场景交付，每个场景的东西加起来不超过上面的预算；单个模型的面数上限见各需求文档。
- **烘焙光照**：静态的建筑、地形、大石头，把环境光遮蔽（AO）和柔和的阴影直接画进贴图（或第二套 UV 的光照贴图）。效果比实时阴影细腻，运行时几乎不花钱。
- 同类小东西（花、草、石头、栅栏）做成可以实例化的单个模型，不要每个都不一样。
- 远景（只能看的山、远处的树林）单独做低面数版本，不需要细节。
- 不要在模型里画雪（程序按季节自动加）。

## 6. 场景切换（程序）

- 世界地图（`openWorldMap`）列出所有场景；规划中的显示「未开放」。
- 切换时淡出 → 释放当前场景 → 生成 / 加载新场景 → 淡入；家园在后台暂停，回家时不用重新加载。
- 以后：在传送阵附近提前加载目标场景的美术资源，切换控制在 2~3 秒内。
