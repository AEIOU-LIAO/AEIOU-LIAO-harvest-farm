# 丰收农场 · 架构设计（V0 起）

2026-10-25 · 适用版本 3.4 起 · 维护：Claude（程序）· 决策：甲方

> 目标：把「一张农场地图的种菜游戏」改造成一个可以不断扩展的大世界网页游戏，后续按赛季加入区域、生物、建筑、武器、江湖玩法。**每次改造都不影响现有玩家的数值、存档和玩法。**

## 1. 定位与约束

| 项 | 决定 |
|---|---|
| 主要玩家 | 甲方本人（深度玩家）为主，家人朋友作为「江湖中人」一起玩 |
| 平台 | 手机浏览器（iPhone Safari / 微信内置浏览器 / 安卓 Chrome）优先，电脑兼容 |
| 运行环境 | EdgeOne Pages 免费版（静态文件 + 云函数，定时任务最短一天一次）；Turso 免费额度（SQLite 兼容） |
| 结算 | **服务器权威**：所有数值结算在服务器，前端只负责显示和插值（防作弊，也为以后开放给别人留余地） |
| 实时性 | 不做实时长连接（云函数无状态）。社交玩法做成异步（轮询、排行、留言、异步挑战）。需要实时多人时再评估付费服务 |
| 发布节奏 | 每周一个小版本、每个赛季（4~6 周）一个大版本；每次推送到 `edgeone` 分支自动部署 |
| 美术管线 | 美术仓库 `AEIOU-LIAO-harvest-farm-art` 交付 GLB → 程序验收 → 预览页真机确认 → 打包进游戏 |

## 2. 现状（3.3.x）

```
index.html（构建生成，单文件）
 ├─ shared/config.js   规则 + 全部内容表（作物 108、果树 18、羊 12、鱼 14、狗、商品、任务、成就…）
 ├─ src/world3d.js     Three.js r149 场景：农场 / 牧场 / 鱼塘 / 果园全部在一张地图里；人物和狗由代码拼形状
 ├─ src/game.js        交互、音效、弹窗、输入
 └─ src/ui.js          各弹窗
server/（Node，async）
 ├─ app.js   路由（约 100 个接口）     ├─ game.js  玩法结算（农场、牧场、狗、商店…）
 ├─ db.js    SQLite / Turso + 迁移      └─ npc.js   10 个 AI 邻居
art-preview.html  美术资源手机预览页（GLB 加载、gzip、贴图分档）
```

瓶颈：① 内容写死在代码里，加内容要改代码；② 所有东西在一张地图，扩展就卡；③ 角色是代码拼的，不能直接用美术的骨骼模型；④ 前端单文件，体积随内容增长。

## 3. 目标架构

```
content/                  ← 内容数据（JSON），策划改这里，不改逻辑代码
 ├─ crops.json fish.json sheep.json trees.json dogs.json shop.json …（现有内容）
 ├─ zones.json            区域登记表（家园 + 规划中的区域）
 ├─ assets.json           美术资源清单（模型、贴图档位、动作、配件）
 └─ （以后）creatures.json buildings.json weapons.json seasons.json quests.json …
tools/build-content.js    校验 + 生成 shared/content.js（前后端共用）
shared/config.js          只放规则和公式（经验曲线、价格公式、结算函数），内容从 content 读
src/
 ├─ （lib/assets3.js）     资源库：按清单加载 GLB（gzip）、贴图分档（手机 1K / 高清 2K）、缓存、引用计数释放
 ├─ entity.js（V0.2）      实体：模型 + 动作状态机（idle / walk / … 缺省回退）+ 配件切换
 ├─ zones.js（V0.2）       场景系统：一个区域一个场景，进入时加载、离开时释放；每个区域有性能预算
 ├─ world3d.js            家园区域（现有农场场景，逐步拆分）
 └─ game.js / ui.js       交互与界面（逐步拆成按玩法的模块）
server/
 ├─ game.js               按领域逐步拆分：农业 / 生物 / 狩猎战斗 / 建造 / 任务剧情 / 经济 / 社交
 └─ （以后）domains/*.js
```

### 3.1 内容数据化

- 每张内容表一个 JSON 文件；**构建时**校验（必填字段、id 连续唯一、等级递增、引用存在）并生成 `shared/content.js`。
- 公式类内容（比如 Lv.50~3800 的 60 种高阶作物）在 JSON 里写**生成参数**（名字前缀、模板、颜色、数量、等级范围），公式留在代码里。
- 改造前后用快照测试证明内容完全一致（`test/content.test.js`）。
- 以后管理后台可以在线覆盖部分数值（活动倍率、限时商品），不用发版。

### 3.2 区域（场景）系统

- 世界由多个区域组成：家园（现有农场）、名山、河谷、沙漠、雪岭、龙脊山脉……
- 一个区域 = 一份区域数据（地形、天空、季节表现、可出现的生物、建筑点位、解锁条件）+ 一组资源。
- 同一时刻只加载当前区域（加上家园的必要部分）；切换区域像现在串门一样，有过场、按需下载。
- 每个区域有预算：同屏三角面 ≤ 30 万、绘制次数 ≤ 150、贴图显存 ≤ 150 MB（手机），由预览页 / 测试脚本检查。

**V0.3 已实现**（`src/zones.js`）：
- `Zones.enter(id)`：淡出 → 释放上一个区域（`disposeTree` 释放全部几何体、材质、贴图）→ 生成 / 加载新区域 → 淡入。家园在后台暂停渲染、不响应点击（`W3.useZone`）。
- 区域对象接口：`{ scene, camera, update(dt), resize(w, h), dispose() }`；`Zones.BUILDERS[id]` 注册生成函数。
- 野外生成：`Zones.generate(gen, seed)` 只依赖种子和 `content/biomes.jsonc`，不依赖 Three.js（以后服务器可以用同一个种子算刷怪点、掉落点，前后端一致）。
- 世界地图（侧栏「地图」）：列出 live / planned 区域；`dev` 区域只在网址带 `?dev=1` 时显示。

### 3.2.1 家园建造网格（V0.3）

- `content/home.jsonc`：家园所有固定建筑、菜地、池塘、牧场、果园的位置和占地；`src/world3d.js` 和服务器都读它。
- `CFG.homeOccupancy({ fields, pastLv, pondLv })`：2 米一格（65 × 66 格），标出被菜地 / 建筑 / 池塘 / 牧场 / 果园占用的格子；满级后仍有约 2500 格可以自由建造。
- `CFG.canPlace(occ, items, item, lv)`：开放状态、等级、数量上限、越界、占用、重叠检查，返回中文原因。
- 存档 `users.layout`（迁移 v5）：`{ v, seq, items: [{ id, type, gx, gz, rot, at }] }`；接口 `GET /api/home/layout`、`POST /api/home/place`、`POST /api/home/remove`（退一半）。扩建牧场 / 鱼塘、开新菜地后，被占用格子上的建筑自动收回并全额退款。
- 建筑目录 `content/buildings.jsonc` 目前全部 `planned`，第 1 期上线摆放界面时改为 `live`。

### 3.3 资源管线与实体

- 美术交付 → `tools/pack_art.py`：去掉内嵌图片、网格 gzip、贴图出手机版 1024 和高清 2048 → `art/<版本>/<资源>/`。
- `content/assets.json` 登记每个资源：路径、类型（人物 / 狗 / 建筑 / 生物）、尺寸、动作列表、配件、贴图档位、状态（候选 / 验收通过 / 上线）。
- `src/assets.js` 统一加载：gzip 解压（不支持时回退）、iOS 兼容（不用内嵌图片解码）、缓存、引用计数释放显存。
- 实体（V0.2）：人物、狗、羊、野兽、龙用同一套机制 —— 模型 + 动作状态机 + 行为（巡逻、跟随、逃跑、攻击）。缺动作时按规则回退（`trot`→`walk`→`idle`），美术分批交动作也能先上线。

### 3.4 服务器

- 继续「玩家打开时补算」（懒计算）：作物生长、牧场、季节、兽潮、离线收益都在请求时按时间差结算（免费版定时任务一天一次）。
- 战斗、狩猎：**服务器出结果、前端演出**。服务器按装备、等级和随机种子算出胜负、掉落，前端播放过程。
- 数据：已有玩法用现有表；新玩法优先用玩家 JSON 列（像牧场 `users.ranch` 一样）+ 必要时新表；每次加表 / 加列都写迁移（`server/db.js` MIGRATIONS），老存档自动升级。
- 免费额度预算：每次操作 ≤ 2 次写入；轮询统一走 `/api/poll`。

### 3.4.1 服务器玩法模块（V0.4）

- `server/game.js` 只留核心：配置覆盖、活动倍率、事务缓存、玩家 / 土地 / 背包 / 金币 / 经验 / 计数器 / 消息 / 可见性、概况。
- 玩法在 `server/domains/`：`account` 账号 · `farm` 农田 · `ranch` 牧场与狗 · `home` 家园建造 · `quest` 任务成就订单 · `social` 好友串门偷菜 · `economy` 集市排行赛季；共用工具在 `common.js`。
- 每个模块导出一组方法，启动时挂到 `Game.prototype`（重名直接报错），`this` 仍是 Game 实例，接口层（`server/app.js`）调用方式不变。新玩法（狩猎、战斗、奇观）各加一个模块。
- 云函数打包（`deploy/bundle-functions.js`）只认字面量 `require`，新加模块要同时登记到 `game.js` 的 `DOMAINS` 和打包脚本的 `MODS`。

### 3.5 前端

- 构建从「拼接单文件」逐步改为「首屏核心 + 按需加载的模块」：家园首屏只加载必要代码，区域、玩法模块进入时才加载。
- **V0.4 已做**：`needScripts()`（`src/net.js`）按需加载 `vendor/three-addons.js`、`lib/assets3.js`、`lib/entity3.js`（进区域、开新角色时）；启动时 `/api/config`、`/api/state` 先发出再生成场景；加载画面盖着时暂停渲染；狗和作物图标在画面出来后生成（`W3.afterShown`），作物图标按版本号存在本机。
- **启动耗时遥测**：`BOOT_T`（js 脚本就绪 / w3 场景生成完 / cfg 配置到达 / shown 画面出来）随 `/api/telemetry` 上报，按天累计在 metrics（`boot_*_ms`）。以后按真机数据决定下一步优化什么。
- 所有界面文字中文；手机优先（触摸、单手、竖屏 / 横屏）。

### 3.6 与沙盒游戏（我的世界 / 迷你世界）的关系（2026-10-25 甲方确认）

**不照搬沙盒架构，借鉴它的长处。** 沙盒的核心是方块化、可破坏的无限世界 + 常驻实时服务器；这在免费的云函数和手机网页上成本太高，也会和种田、牧场的核心玩法割裂。我们的核心是「模拟经营 + 开放世界探索成长」。

| 借鉴 | 做法 |
|---|---|
| 数据包 / 注册表 | `content/*.jsonc` + 构建校验（V0.1 已完成） |
| 实体 + 组件 | 所有生物用同一套「模型 + 动作状态机 + 行为」（V0.2） |
| 程序生成 | 野外区域（名山猎场等）用「种子 + 生物群系表」生成地形、植被和刷怪点，每次去略有不同，不需要美术逐张画（第 2 期起） |
| 自由建造 | 家园改为格子地图：城墙、箭塔、奇观、装饰可以自由摆放 / 拆除 / 旋转；布局存成每个玩家一份 JSON（V0.3 区域系统时设计，第 1 期上线） |

**不做**：可破坏的方块地形、无限世界、实时多人同屏（成本最高、也最偏离种田核心）。

## 4. 运营设计

| 循环 | 内容 |
|---|---|
| 每日 | 收获、喂养、签到、每日任务、日常狩猎 |
| 每周 | 周任务、周首领、兽潮防御 |
| 每赛季（4~6 周） | 季节切换 + 一个新区域或奇观阶段 + 一批生物 / 武器 + 限时活动 |
| 长线 | 4000 级里程碑：新区域、新境界、奇观阶段、神兽 |

- **经济**：后期金币来源多、消耗少。奇观建造、武器锻造、神兽培养作为大额消耗点；每次加新产出都要配对应的消耗。
- **数据**：遥测接口记录玩了什么、停在哪里、在哪卡关，用来调数值、定下一季内容。
- **分工**：甲方定方向和验收；程序写设计文档、数据表、代码、数值；美术按需求文档交资源。

## 6. 规则（所有版本遵守）

1. 不改变现有玩家的数值和存档，除非版本说明里写明并经甲方同意。
2. 内容改动走 `content/`，逻辑改动走代码，二者分开提交。
3. 新玩法先在预览页或测试开关下验证，再上线。
4. 每个版本：`npm test`、`npm run test:turso`、浏览器回归脚本全过；`docs/ACCEPTANCE.md` 记录需求 / 处理 / 验证。
5. Turso 密钥只放环境变量，绝不提交。
